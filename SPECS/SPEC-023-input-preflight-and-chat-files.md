## 1. Files in the chat (no model)
- `rfq-chat-intent.ts` `filesIntent`: files attached + "process / run / use / go / select / map / upload ... files / these / it" (and a bare "go") -> create path. No RFQ id in the text, not a how-to, and not when one RFQ is open.
- `resolveFiles` reads what is INSIDE each released file (roles from `attachment_roles.py`): non-spreadsheets are "left out as reference only" (not a refusal any more), exactly one SCRUB BOM workbook is the BOM (its Settings sheet stands in as the volume file: `/api/rfq/upload` needs a volume file, the pipeline ignores it), two -> ask which, none -> a bullet list of what each spreadsheet is and what to attach.
- Customer / project: a reply that waits starts with `CREATE_PENDING`; the next turn (typed or a pressed button: `disambiguate` options now carry an optional `send` text) is read together with the user's earlier turns. No "repeat the whole request".
- The general chat model is told the attached file names exist (it can never say it has none).
- Chips show the role (`BOM`, `Volume`, `QuoteWin`, `Reference`, `Not recognised`, `BOM: N to fix`), 4 chips then "+N more", the message list scrolls to the newest reply when the tray changes.

## 2. Pre-flight (`fastapi-router/input_check.py`)
Reads the SCRUB BOM / Settings / Batch sheets like `standardize_scrub_bom` does (values AND formulas, from memory so Windows keeps no file lock) and lists every cell that would be NaN / empty / an Excel error: pandas NA tokens (`N/A`, `NaN`, `null`, `None` ...), `#REF!` etc., formulas with no saved result, text or negative quantity, blank CPN / FG, blank or non-numeric volume, FG missing from Settings, missing SCRUB BOM sheet or required column. Errors stop the start, warnings (blank MPN / description / manufacturer / commodity / part status, bad LTB date, zero quantity, blank batch) do not. It cannot import the real step (ollama, mcp-tools are not in the bridge image), so `testing/test_input_check.py` runs the real `process_volume_sheet` / `standardize_scrub_bom` on the same data and asserts every NaN cell was flagged.
- Bridge: `GET .../attachments/{id}/check`, `POST .../attachments/{id}/fix {edits:[{sheet,row,col,value}]}` (applies to a COPY, scans it with BOTH engines again, releases it as `<name>_corrected.xlsx` in place of the original; values typed, text starting `= + - @` refused, 500 edits max). The corrected copy keeps each formula's last calculated VALUE, not the formula: openpyxl cannot save a formula with its result and a formula without one reads as NaN (found by the live proof).
- Upload service `/api/rfq/upload` refuses an invalid BOM with 422 `{code:"input_invalid", issues}` before any version or run exists (Standard_BOM_Flow only). The old intake modal shows the first cells.
- Scan results and the file list carry `check:{errors,warnings}`.

## 3. Fix dialog (`InputFixDialog.tsx`)
Only the flagged cells, each with address, column, what is wrong and a box (a suggestion button for text that is a number); problems no cell can fix (missing sheet / column / FG row) are listed as "needs Excel"; warnings are optional and folded. Save -> re-check -> when clean the corrected file is downloaded to the computer (a click started it) and "Continue with this file" carries on (chat: sends "create an RFQ from these files"; intake dialog: Create RFQ button appears). Used from the chat (`fix_input` directive) and from the intake dialog results.

## 4. Left pane from the manifests

"Scan for virus" is a button that opens Settings, Security. The stage ids and progress mapping are unchanged; this is the UI only, the pipeline itself does not read `enabled`.
